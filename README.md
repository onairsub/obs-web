# OBS Multi-Sports Controller

OBS Studio 옆에 작은 세로 창으로 띄워 사용하는 스포츠 중계 컨트롤러입니다. OBS가 실행 중인 컴퓨터의 로컬 웹은 `ws://localhost:{port}`를 통해 OBS WebSocket v5에 직접 연결합니다. 모바일 원격 제어는 Vercel WebSocket Function과 Upstash Redis Pub/Sub을 통해 인터넷으로 중계합니다.

지원 종목:

- 축구: `/obs/soccer`
- 농구: `/obs/basketball`
- 야구: `/obs/baseball`
- 배구: `/obs/volleyball`

로그인에 성공하면 `/obs/sports`에서 종목을 선택합니다.

앱 안의 `/obs/help`에서 종목별 OBS 소스 이름과 준비 순서를 확인할 수 있습니다. 스포츠 선택 화면과 각 컨트롤러 하단의 `도움말` 링크로 열면 현재 종목이 자동으로 선택됩니다.

OBS가 실행 중이지 않을 때는 로그인 화면의 `OBS 없이 프리뷰` 버튼으로 들어갈 수 있습니다. 프리뷰 모드에서는 점수, 타이머, 세트와 카운트 조작이 브라우저 안에서 정상 동작하고 저장되지만 OBS WebSocket 요청은 전송되지 않습니다. 컨트롤러 상단의 `Preview`를 누르면 언제든 연결 화면으로 돌아갑니다.

## 요구 사항과 실행

- OBS Studio 28.1.2 이상
- OBS와 이 웹 앱을 같은 컴퓨터에서 실행
- OBS WebSocket v5 활성화(기본 포트 `4455`)
- Node.js와 pnpm

```bash
pnpm install
pnpm dev
```

로컬 개발 실행은 Vercel과 같은 프로토콜을 시험할 수 있도록 웹 페이지와 WebSocket을 함께 실행합니다. 프로덕션 셀프 호스팅은 `pnpm build` 후 `pnpm start`를 사용합니다.

브라우저에서 `http://localhost:3000/obs`를 엽니다. OBS의 `도구 → WebSocket 서버 설정`에서 서버를 활성화하고, 앱 로그인 화면에 같은 포트와 비밀번호를 입력합니다.

## 모바일 원격 제어

OBS 연결이 완료된 로그인 화면이나 스포츠 선택 화면에서 `원격 컨트롤 열기`를 누릅니다. 표시된 Vercel 주소를 휴대폰에서 열면 네트워크가 달라도 접속할 수 있습니다.

- 휴대폰은 OBS에 직접 연결하지 않고 Vercel WebSocket을 통해 호스트 브라우저에 명령을 보냄
- OBS 비밀번호와 접속 정보는 휴대폰이나 중계 세션으로 전송하지 않음
- 점수, 타이머, 경기 구간, 팀 상태와 현재 종목은 호스트와 모바일에서 양방향으로 즉시 동기화
- 모바일에서 종목을 변경하면 호스트 컨트롤러도 같은 종목으로 이동
- 타이머는 OBS 호스트에서만 상태를 확정합니다. 여러 모바일은 시작·정지·리셋·보정 명령을 보내며, 호스트의 최신 값에 순서대로 반영됩니다.
- 모바일 시계 차이는 호스트 왕복 통신으로 보정하고, 중복 명령·오래된 상태는 무시합니다. 타이머가 0초에 도달해도 모바일이 호스트 시간을 덮어쓰지 않습니다.
- 재연결 시 타이머는 실행 중인 호스트에서 다시 받아 옵니다. `동기화 중`에는 타이머 조작이 비활성화되며, 끊긴 동안의 조작을 나중에 재전송하지 않습니다.
- Vercel Function의 5분 연결 만료 전에(연결 후 약 4분 20~30초) 새 소켓을 준비해 교체합니다. 기존 연결의 조작 처리가 끝난 것을 확인한 뒤 전환하며, 교체 중 타이머·화면·원격 링크를 유지합니다.
- 교체 중 두 소켓으로 도착한 같은 이벤트는 한 번만 처리합니다. 새 연결 준비에 실패하면 기존 연결을 유지하며 다시 시도합니다.
- 예기치 않은 네트워크 단절은 자동 재연결하고, 타이머 동기화 응답이 없으면 처음에는 0.5초 간격으로 빠르게 재시도합니다(장시간 응답이 없으면 최대 5초로 간격을 늘림). 호스트·모바일 탭이 절전 상태이거나 실제 인터넷 연결이 끊긴 동안에는 원격 조작이 제한될 수 있습니다.
- 링크의 무작위 세션 키는 `원격 컨트롤 닫기`를 누르면 즉시 무효화

원격 연결 프로토콜(v3)이 변경된 버전으로 배포한 뒤에는 호스트와 모바일 페이지를 모두 새로고침하고 원격 링크를 다시 열어 주세요. OBS 호스트 브라우저는 경기 중 계속 실행되어 있어야 합니다.

동기화 회귀 테스트는 `pnpm test:clocks`로 실행합니다. 임시 Redis를 지정해 `CLOCK_TEST_REDIS_URL=redis://127.0.0.1:16389 pnpm test:clocks`를 실행하면 별도 서버 인스턴스 두 개와 모바일 세 개 사이의 Pub/Sub 중계까지 검증합니다.

연결 교체 회귀 테스트는 `pnpm test:connection`입니다. `CLOCK_TEST_REDIS_URL`을 지정하면 서로 다른 서버 인스턴스로 연결을 교체하면서 중복 조작·상태 되돌림·접속 중단 여부를 검증합니다. 운영 중계의 장시간 점검은 별도의 테스트 세션으로 `CLOCK_TEST_WS_URL=wss://obs-web-onairsub.vercel.app/api/remote-ws RENEWAL_TEST_INTERVAL_MS=260000 RENEWAL_TEST_DURATION_MS=330000 RENEWAL_TEST_STEP_MS=1000 pnpm exec tsx --test scripts/remote-renewal.test.ts`를 실행합니다.

### 키보드 단축키

각 점수판의 **점수 초기화** 버튼은 확인 후 해당 점수판의 양 팀 점수만 0점으로 만듭니다. 타이머·쿼터·파울·세트 승수 등 다른 기록은 유지되고 원격에도 반영됩니다. 축구 PK 점수판의 버튼은 PK 점수만 초기화합니다. 오조작 방지를 위해 초기화 단축키는 없습니다.

각 컨트롤러의 **키보드 단축키**를 펼치면 메뉴별 키 배치를 볼 수 있고, 이 브라우저에서만 켜거나 끌 수 있습니다. 종목별 도움말에도 같은 안내가 표시됩니다. 모든 조작은 **키 하나**로 실행하며 같은 메뉴는 인접한 키에 배치했습니다.

단축키가 있는 버튼 안에는 해당 키가 작은 배지로 표시됩니다. 농구의 `Space` 표시는 현재 실행 상태에 따라 **둘 다 시작 / 둘 다 정지** 버튼 사이에서 이동합니다.

| 종목 / 메뉴 | 키 순서 | 동작 순서 |
| --- | --- | --- |
| 공통 A팀 점수 | `U I` | −1점 / +1점 |
| 공통 B팀 점수 | `J K` | −1점 / +1점 |
| 농구 A팀 점수 | `U I O P` | −1점 / +1점 / +2점 / +3점 |
| 농구 B팀 점수 | `J K L ;` | −1점 / +1점 / +2점 / +3점 |
| 농구 동시 타이머 | `Space` | 하나라도 실행 중이면 둘 다 정지, 모두 멈춰 있으면 둘 다 시작 |
| 농구 게임클락 | `Q W E R` | 시작·정지 / −1초 / +1초 / 쿼터 리셋 |
| 농구 샷클락 | `A S D F G` | 시작·정지 / −1초 / +1초 / 기본 리셋 / 리바운드 리셋 |
| 농구 파울 | `Z X C V` | A팀 −1 / A팀 +1 / B팀 −1 / B팀 +1 |
| 축구 경기 시계 | `Q W E R` | 시작·정지 / −1분 / +1분 / 00:00 리셋 |
| 축구 추가시간 | `A S` | −1분 / +1분 |
| 야구 타석 | `Q W E R` | 볼 / 스트라이크 / 아웃 / 볼·스트라이크 초기화(아웃 유지) |
| 야구 주자 | `A S D` | 1루 / 2루 / 3루 표시 전환 |
| 배구 서브권 | `Q W E` | A팀 / 끔 / B팀 |
| 배구 타임아웃 표시 | `A S D` | A팀 전환 / 끔 / B팀 전환 |

- 전역 OBS 단축키가 아닙니다. **컨트롤러 웹페이지에 포커스가 있어야** 합니다. 호스트·원격·프리뷰 모두 같은 버튼 동작을 사용하며, 원격 타이머는 호스트가 확정합니다.
- 입력창, 선택 메뉴, 단축키 안내 영역, 한글 조합 중에는 동작하지 않습니다. 한/영 모드와 무관하게 영문 키 위치를 사용하고 Ctrl/Alt/Command/Shift 조합은 가로채지 않습니다.
- 길게 눌러도 한 번만 반영됩니다. 원격 연결이 끊기면 단축키가 중지되며 타이머 동기화 중에는 시간 조작을 받지 않습니다.
- 농구 리셋은 설정한 쿼터·기본 샷클락·리바운드 샷클락 시간을 따르고, 실행 중이면 실행을 유지합니다. `Space`는 컨트롤 버튼에 포커스가 있어도 타이머를 제어합니다. 선택한 버튼 실행은 `Enter`를 사용하세요.
- 팀 교대·세트 종료·전체 경기 초기화는 오조작을 줄이기 위해 단축키를 배정하지 않았습니다.

단축키 회귀 테스트: `pnpm test:shortcuts`

### Vercel 원격 중계 설정

무료 운영은 개인·비상업 용도의 Vercel Hobby와 Upstash Redis Free 조합을 권장합니다. 이 앱은 Redis Stream 폴링을 하지 않고 실제 상태 변경과 접속 이벤트만 Pub/Sub으로 전달하므로 간헐적인 경기 운영에서는 무료 명령량을 아껴 사용합니다. 경기가 끝나면 `원격 컨트롤 닫기`를 눌러 연결을 종료하세요.

1. GitHub 저장소를 Vercel의 `New Project`에서 가져와 첫 배포를 실행합니다.
2. 프로젝트의 `Storage` 또는 Marketplace에서 Upstash를 선택하고 Redis의 Free 데이터베이스를 만듭니다.
3. 생성한 데이터베이스를 프로젝트에 연결하고 `REDIS_URL` 환경 변수가 추가됐는지 확인합니다. 이 값은 Vercel 서버에만 둡니다.
4. Vercel 프로젝트 환경 변수에 `NEXT_PUBLIC_REMOTE_ORIGIN=https://배포주소.vercel.app`을 추가한 뒤 다시 배포합니다.
5. OBS 컴퓨터의 프로젝트 루트에 `.env.local`을 만들고 같은 `NEXT_PUBLIC_REMOTE_ORIGIN`만 입력합니다. 로컬 컴퓨터에는 `REDIS_URL`이 필요하지 않습니다.
6. OBS 컴퓨터에서 `pnpm install`, `pnpm build`, `pnpm start` 순서로 실행하고 `http://localhost:3000/obs`로 접속합니다.

호스트 화면은 반드시 OBS가 실행 중인 컴퓨터의 로컬 주소로 열어야 합니다. Vercel 배포본은 모바일 화면과 원격 WebSocket 중계를 담당합니다. Redis가 없으면 한 Function 인스턴스 안에서는 동작할 수 있지만 호스트와 모바일이 서로 다른 인스턴스에 배정될 수 있으므로 실제 배포에서는 `REDIS_URL`이 필수입니다. Vercel WebSocket이 Fluid Compute를 사용하도록 프로젝트 설정도 확인하세요.

## OBS 소스 준비 원칙

이 앱은 OBS 입력 및 씬 아이템의 이름을 정확하게 찾아 제어합니다. 대소문자와 언더스코어까지 아래 표와 일치해야 합니다.

- 텍스트 값: OBS의 텍스트 입력(Text GDI+ 또는 FreeType 2)으로 생성
- 표시/숨김: 현재 프로그램 씬 안의 씬 아이템으로 생성
- 이미지 자산: Image Source, 속성 `file` 사용
- 영상 자산: Media Source, 속성 `local_file` 사용
- 사용하지 않는 기능은 해당 OBS 소스를 만들지 않아도 됩니다.

| `team_B` | 텍스트 입력 | B 팀 이름 |

컨트롤러 상단의 장면 선택 메뉴는 OBS의 프로그램 장면을 전환합니다. 표시/숨김 조작은 현재 프로그램 장면에 있는 같은 이름의 아이템을 모두 변경합니다.

## 축구 설정

제공 조작: 득점, 전후반/연장/PK 구간, 카운트업 경기 시계, 추가시간, 퇴장 수, 승부차기 점수.

| OBS 이름 | 종류 | 값/동작 |
| --- | --- | --- |
| `game_clock` | 텍스트 입력 | `MM:SS` 경기 시계 |
| `period` | 텍스트 입력 | `전반`, `HT`, `후반`, `연장1`, `연장2`, `PK`, `FT` |
| `added_time` | 텍스트 입력 + 씬 아이템 | `+N`; 0이면 숨김 |
| `red_cards_A` | 텍스트 입력 | A 팀 퇴장 수 |
| `red_cards_B` | 텍스트 입력 | B 팀 퇴장 수 |
| `penalties_A` | 텍스트 입력 | A 팀 승부차기 득점 |
| `penalties_B` | 텍스트 입력 | B 팀 승부차기 득점 |

설정 화면에서 전반·후반·연장 전후반 시간을 분 단위로 지정합니다. 컨트롤러에는 전반 시작, 후반 시작, 연장 시작, 연장 후반 시작 프리셋이 설정값을 합산한 시각으로 표시됩니다. 시계는 자동으로 구간을 전환하지 않으므로 실제 경기 진행에 맞춰 운영자가 구간을 선택합니다.

## 농구 설정

농구는 게임클락과 샷클락을 서로 독립된 타이머로 제공합니다. `둘 다 시작/정지`와 개별 시작/정지를 모두 지원합니다.

제공 조작: 1·2·3점 득점, 게임클락, 24/14초 샷클락, 쿼터, 팀 파울, 타임아웃, 공격권.

| OBS 이름 | 종류 | 값/동작 |
| --- | --- | --- |
| `game_clock` | 텍스트 입력 | 설정한 쿼터·연장 시간 |
| `shot_clock` | 텍스트 입력 | 설정한 기본·공격 리바운드 시간; 5초 미만은 `4.9` 형식 |
| `period` | 텍스트 입력 | `Q1`, `Q2`, `Q3`, `Q4`, `OT`, `FT` |
| `fouls_A` | 텍스트 입력 | A 팀 팀 파울 |
| `fouls_B` | 텍스트 입력 | B 팀 팀 파울 |
| `fouls_A_1` ~ `fouls_A_9` | 씬 아이템(선택) | A 팀 파울 수 이하의 마커만 표시 |
| `fouls_B_1` ~ `fouls_B_9` | 씬 아이템(선택) | B 팀 파울 수 이하의 마커만 표시 |
| `timeouts_A` | 텍스트 입력 | A 팀 사용/잔여 표시에 활용할 숫자 |
| `timeouts_B` | 텍스트 입력 | B 팀 사용/잔여 표시에 활용할 숫자 |
| `possession_A` | 씬 아이템 | A 팀 공격권일 때 표시 |
| `possession_B` | 씬 아이템 | B 팀 공격권일 때 표시 |

게임클락은 1분 미만에서 `59.9` 형식으로 표시합니다. 샷클락은 게임클락이 멈춰도 독립 실행할 수 있으며, 실행 중인 게임클락과 샷클락은 리셋이나 ±1초 보정 후에도 새 값에서 계속 실행됩니다.

**샷클락은 0초에 도달해도 RUN 상태를 유지**합니다. 표시는 `0.0` 아래로 내려가지 않으며, 이때 24초·14초 프리셋이나 직접 입력·시간 추가를 적용하면 즉시 새 값에서 카운트다운합니다. `일시정지` 또는 `둘 다 정지`를 누르면 실행 상태가 해제되고, 이후 값을 설정해도 자동 실행하지 않습니다. PC·원격 모바일에 동일하게 적용되며 게임클락의 0초 종료 동작은 그대로입니다.

배포 후에는 **OBS에 연결된 호스트 PC와 모바일을 모두 새로고침**하세요. 모바일만 업데이트하고 호스트가 이전 타이머 코드를 계속 실행하면, 모바일에는 `0.0 / RUN`으로 보여도 호스트가 24초 재설정을 정지 상태로 처리할 수 있습니다. 이제 호스트의 타이머 버전을 확인하고, 버전이 다르면 `호스트 PC 새로고침 필요` 안내와 함께 타이머 조작을 차단합니다. 호스트를 새로고침해 호환 버전이 확인되면 조작이 다시 활성화됩니다. 점수 등 다른 경기 조작과 원격 연결은 유지합니다.

게임클락·샷클락 **숫자를 더블클릭**하면 같은 크기·위치의 테두리 없는 입력 필드로 바뀝니다. 모바일은 **두 번 탭**, 키보드는 숫자에 포커스 후 Enter/Space로 열 수 있습니다. 게임클락은 `02:34.5`처럼 분:초 또는 `59.9`처럼 초만 입력하고, 샷클락은 초를 입력하세요. **Enter 또는 바깥 클릭**으로 적용하며 **Escape**로 취소합니다. 0.1초 단위를 지원하고 최대 24시간까지 입력할 수 있습니다. 잘못된 값은 적용하지 않습니다. 입력 중에는 시계를 멈추지 않으며, 적용 당시의 실행·정지 상태를 유지합니다. 게임클락은 `0초`로 설정하면 정지하고, 실행 중인 샷클락은 `0초`로 설정해도 RUN 상태를 유지합니다. PC와 원격 모바일 모두 사용할 수 있으며, 원격 입력도 호스트가 확정한 값으로 모든 기기에 동기화됩니다.

다른 쿼터(연장·종료 포함)를 선택하면 **양 팀 파울·타임아웃을 0으로 초기화**합니다. 같은 쿼터를 다시 누르거나 단순히 원격 상태를 동기화할 때는 초기화하지 않습니다. 점수·타이머·공격권은 유지됩니다.

파울은 기존 `fouls_A`, `fouls_B` 숫자 텍스트와 선택형 마커를 동시에 지원합니다. 예를 들어 A 팀 파울이 2이면 `fouls_A_1`, `fouls_A_2`만 표시되고 나머지는 숨겨집니다. 필요한 마커 개수만큼만 현재 프로그램 씬에 추가하면 됩니다.

파울 값이 바뀌면 호스트가 텍스트·마커 적용 완료를 확인한 뒤 **현재 프로그램 장면에 한 번 전환**합니다. OBS에 지정된 전환 효과를 사용하며, 스튜디오 모드의 다른 미리보기 장면을 송출하지 않습니다. 최초 연결·같은 값 재수신에는 전환하지 않고, 연속 변경은 순서대로 처리합니다. 적용 중 운영자가 다른 장면으로 이동했다면 이전 장면으로 되돌리지 않습니다. 스튜디오 모드나 전환 설정 자체는 변경하지 않으며, 실제 같은 장면 전환 효과는 OBS의 모드·장면 복제 설정에 따릅니다.

## 야구 설정

제공 조작: 득점, 이닝과 초/말, B/S/O, 주자, 안타, 실책.

| OBS 이름 | 종류 | 값/동작 |
| --- | --- | --- |
| `inning` | 텍스트 입력 | 현재 이닝 숫자 |
| `inning_half` | 텍스트 입력 | `TOP` 또는 `BOTTOM` |
| `balls` | 텍스트 입력 | 볼 카운트 0~3 |
| `strikes` | 텍스트 입력 | 스트라이크 카운트 0~2 |
| `outs` | 텍스트 입력 | 아웃 카운트 0~2 |
| `hits_A`, `hits_B` | 텍스트 입력 | 팀별 안타 |
| `errors_A`, `errors_B` | 텍스트 입력 | 팀별 실책 |
| `base_1` | 씬 아이템 | 1루 주자 표시 |
| `base_2` | 씬 아이템 | 2루 주자 표시 |
| `base_3` | 씬 아이템 | 3루 주자 표시 |

네 번째 볼은 타석 카운트를 초기화하고, 세 번째 스트라이크는 아웃을 올립니다. 세 번째 아웃은 주자를 비우고 공수를 교대하며, 말 공격 종료 시 다음 이닝으로 넘어갑니다. 현장 판정 정정은 `카운트 초기화`와 이닝 ± 버튼으로 보정합니다.

## 배구 설정

제공 조작: 득점, 세트 승수, 자동 세트/매치포인트, 서브권, 타임아웃, 세트 종료.

| OBS 이름 | 종류 | 값/동작 |
| --- | --- | --- |
| `set` | 텍스트 입력 | `1 SET` 형식 |
| `sets_A` | 텍스트 입력 | A 팀 세트 승수 |
| `sets_B` | 텍스트 입력 | B 팀 세트 승수 |
| `timeouts_A` | 텍스트 입력 | A 팀 타임아웃 사용 수 |
| `timeouts_B` | 텍스트 입력 | B 팀 타임아웃 사용 수 |
| `serve_A` | 씬 아이템 | A 팀 서브권 표시 |
| `serve_B` | 씬 아이템 | B 팀 서브권 표시 |
| `time_out` | 씬 아이템 | 타임아웃 배너 표시 |
| `timeout_team` | 텍스트 입력 | 타임아웃 팀 이름 |
| `set_point` | 씬 아이템 | 다음 득점으로 세트 승리가 가능한 경우 표시 |
| `match_point` | 씬 아이템 | 다음 득점으로 경기 승리가 가능한 경우 표시 |
| `point_team` | 텍스트 입력 | 세트/매치포인트 팀 이름 |
| `set_A_1`~`set_A_3` | 씬 아이템 | A 팀 세트 승 표시 |
| `set_B_1`~`set_B_3` | 씬 아이템 | B 팀 세트 승 표시 |

세트 목표 점수는 설정 화면의 `세트별 점수`를 사용합니다. 기본값은 `[25, 25, 15]`이며 항상 2점 차 승리를 적용합니다. 점수 조건을 만족해야 `세트 종료` 버튼이 활성화됩니다.

## 종목별 설정

설정 화면 상단에서 축구, 농구, 야구, 배구를 선택합니다.

- 축구: 전반 시간, 후반 시간, 연장 전·후반 시간
- 농구: 쿼터 시간, 연장 시간, 기본 샷클락, 공격 리바운드 샷클락
- 야구: 정규 이닝 수
- 배구: 세트 수와 세트별 목표 점수
- 공통: 경기 목록과 팀 목록 추가·수정·삭제

로컬 이미지·영상 자산 설정은 현재 설정 화면과 저장 파일에서 제외합니다.

## 설정 저장과 운영 상태

- `SAVE {SPORT} SETTINGS`는 선택한 한 종목의 설정과 공통 경기·팀 목록을 저장
- 파일명은 `obs-soccer-settings.json`처럼 종목을 포함
- JSON 안에도 `sport`, `sportLabel`, `settings`가 기록됨
- 불러오면 파일의 `sport`에 맞춰 설정 탭과 컨트롤 값이 함께 변경됨
- 이전 형식의 `setList`가 있는 파일은 배구 설정 파일로 불러올 수 있음
- 종목별 점수와 타이머는 브라우저 LocalStorage에 자동 저장
- 타이머는 시작 시각을 함께 저장하므로 페이지 새로고침 후에도 경과 시간을 복원
- OBS 접속 포트와 비밀번호도 `OBS-AUTH`에 저장되므로 공용 PC에서는 브라우저 데이터를 삭제할 것

## 문제 해결

- 연결 실패: OBS WebSocket 활성화, 포트, 비밀번호, OBS 28.1.2 이상 여부 확인
- 텍스트 미변경: 입력 이름과 종류를 확인하고 대소문자까지 일치시킬 것
- 표시 토글 실패: 해당 아이템이 현재 프로그램 씬 안에 있는지 확인한 뒤 상단 새로고침 버튼 사용
- 설정값 미반영: 해당 종목 컨트롤 화면으로 돌아간 뒤 프리셋 버튼의 시간이 바뀌었는지 확인
