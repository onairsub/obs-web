# 로컬 전광판 Clock Reader

노트북/USB 카메라의 선택 영역을 읽어 OBS Web 농구 샷클락과 경기 시계에 반영합니다. Python 프로그램이 이 컴퓨터에서 OCR을 실행하고, 브라우저 화면에서 카메라·영역·세션을 설정합니다. 영상이나 OCR 모델은 웹 배포 서버로 보내지 않습니다.

## 실행

Python 3.10 이상이 필요합니다. 이 프로젝트에서는 macOS ARM64 / Python 3.12에서 검증했습니다.

프로젝트 루트에서:

```bash
pnpm clock:reader
```

또는 `bash local-clock/run.sh`. 첫 실행은 `local-clock/.venv`에 라이브러리와 패키지에 포함된 ONNX 모델을 설치하므로 인터넷이 필요합니다. 이후 인식은 오프라인으로 동작하며, 배포된 웹 세션 연결에는 네트워크가 필요합니다. 전역 Python 환경은 변경하지 않습니다.

브라우저에서 **http://127.0.0.1:8765** 를 엽니다. Chrome/Safari 등 카메라 권한을 지원하는 브라우저를 권장합니다. Codex 내부 브라우저에서 카메라가 열리지 않으면 일반 브라우저에서 같은 주소를 여세요. 종료는 실행 터미널에서 `Ctrl+C`입니다. 포트 변경: `pnpm clock:reader --port 8766`.

Windows에서는 다음 명령을 사용합니다:

```powershell
py -3 -m venv local-clock/.venv
local-clock\.venv\Scripts\python -m pip install -r local-clock/requirements.txt
local-clock\.venv\Scripts\python local-clock/app.py
```

## 사용 순서

1. OBS Web 호스트에서 농구 화면과 원격 컨트롤을 열고 공유 링크를 복사합니다. 이 브랜치의 웹 코드가 실행/배포되어 있어야 합니다. 호스트 화면도 계속 열어둡니다.
2. 로컬 화면에서 **카메라 켜기**를 누르고 카메라 권한을 허용합니다. 여러 장치가 있으면 카메라 목록에서 선택합니다.
3. **지정할 영역**에서 샷클락을 선택해 숫자 한 줄을 드래그하고, 게임클락을 선택해 다른 숫자 한 줄을 드래그합니다. 지정된 두 영역을 같은 프레임에서 동시에 읽으며, 한 영역만 지정해도 동작합니다. 콜론/소수점은 포함하고, 점수·팀 이름·다른 시계는 제외합니다. 영역을 백분율 좌표로 입력할 수도 있으며, 마지막 영역은 이 브라우저에 저장됩니다.
4. 공유 링크를 넣고 **세션 연결**을 누릅니다. 세션 ID만 넣었다면 접속할 중계 서버 주소도 입력합니다. 기존 `NEXT_PUBLIC_REMOTE_ORIGIN`이 설정된 경우 그 주소에서 생성된 공유 링크를 사용하세요.
5. 두 시계의 미리보기에서 **확정 인식값**과 **읽은 후보**를 확인합니다. 큰 숫자는 여러 프레임으로 확정한 값이며, 순간 오인식은 후보에만 표시됩니다. `7:00 → 420초`, `3:43 → 223초`, `50.1 → 50.1초`, `24 → 24초`입니다. 샷클락 기본 동기화 최대치는 60초, 경기 시계는 1200초이며 변경할 수 있습니다. 최대값을 초과한 인식은 후보와 사유에 표시하고, 마지막 확정값을 유지하며 전송을 보류합니다. 예를 들어 샷클락 대상으로 `7:00`을 읽으면 `420초 인식됨 · 최대값 60초 초과`로 안내합니다.
6. **동기화 시작**을 누릅니다. 영역·입력·인식 설정 변경이나 페이지 새로고침은 동기화를 끄므로 확인 후 다시 시작하세요. 중계 재연결은 자동이며 연결 중에 쌓인 결과는 재전송하지 않습니다.

카메라 없이 확인하려면 영상 입력에서 **테스트 전광판**을 선택하고 영상 열기 → 영역 선택을 합니다. `50.1`, `7:00` 등 텍스트를 직접 바꾸거나 **숫자 가리기**로 누락 처리를 확인할 수 있습니다.

## 타이머 우선 자동 보정 (기본)

정수 구간은 첫 확정값에서 **1초마다 1씩 감소하는 웹 타이머를 시작**합니다. 카메라가 가려지거나 인식에 실패해도 타이머는 계속 진행합니다. 프레임마다 시계를 다시 설정하지 않습니다.

- 최근 1초의 여러 프레임으로 관찰값을 검증합니다. 일반적인 1초 감소는 그대로 두고, 관찰값이 현재 예측값보다 **2초 이상 작을 때** 확인된 값으로 보정합니다.
- 동일한 관찰값이 **1.2초 이상 계속 확인**되면 실제 전광판이 멈춘 것으로 보고 웹 시계도 정지합니다. 가림/인식 공백 자체는 정지 증거가 아닙니다. 감소가 다시 확인되면 자동으로 재개합니다.
- 샷클락은 **0~24초 범위의 리셋/증가**를 4개 프레임으로 확인한 뒤 반영합니다. 가려진 사이에 14·24로 리셋되어 이미 `13 → 12`로 진행 중이어도 시간에 맞는 감소 흐름이면 복구합니다. 마지막 관찰값보다 작더라도 현재 타이머 예측보다 2초 이상 크면 보정합니다. 24초를 넘는 증가나 새 경기 시간은 **현재 값으로 다시 맞추기**를 사용합니다.
- **초 경계와 처리·통신 지연은 자동 보정**합니다. 확인된 `24 → 23` 전환의 앞뒤 촬영 시각 사이에서 경계를 추정하고, 여러 경계의 원형 중앙값으로 0~999ms 위상을 계산합니다. 관찰값과 웹 시계가 같은 정수 구간에 있어도 오차가 추정 불확실성보다 크면 기준 시각을 보정합니다(최소 250ms 차이, 2초 이상 간격). 기울기는 정지 0 또는 재생 −1로 고정합니다.
- 초 경계를 아직 보지 못한 최초 값은 위상 0에서 시작하며, 감소 전환이 확인되면 정밀해집니다. 숫자 전환 간격이 너무 길거나 리셋·정지·소수 전환이 있으면 오래된 위상을 버립니다. 화면에 추정 위상과 전환 프레임 간격에서 계산한 불확실성을 표시합니다.
- 웹캠은 `requestVideoFrameCallback`의 촬영 시각이 제공되면 사용하고, 없으면 프레임 표시 시각을 기준으로 합니다. 같은 프레임을 복사해 두 영역에 동일한 시각을 붙입니다. 촬영/표시 이후 추론·검증·전송에 걸린 시간은 실제 경과 시간으로 반영하고, 서버 RTT를 별도로 중복 차감하지 않습니다. [브라우저 프레임 시각 API](https://developer.mozilla.org/en-US/docs/Web/API/HTMLVideoElement/requestVideoFrameCallback)
- **추가 영상 지연**은 기본 0초입니다. 폰 카메라/인코더/스트림 내부에서 이미 버퍼링된 지연은 외부 기준 없이 식별할 수 없습니다. 남은 고정 지연을 알고 있다면 여기에 입력합니다(0~3초, 0.05초 단위). 1초를 지정하면 재생 중에만 한 번 앞당깁니다. 자동으로 추정한 초 경계와 추가 지연은 중복 누적되지 않습니다.
- 정지로 판단하면 보정 없이 실제 관찰값으로 맞춥니다. 예: 같은 `20`이 계속 확인되면 웹도 `20`에서 정지합니다.
- **소수 구간은 자동 재생하지 않습니다.** `4.9 → 4.7 → 4.5`처럼 검증된 실제 관찰값만 표시하고, 위상·추가 지연 보정도 적용하지 않습니다. 소수가 가려지면 마지막 확인값을 유지합니다.

**카메라 값만 표시** 모드는 정수도 자동으로 흐르지 않고 확인된 관찰값만 표시하는 선택지입니다. 동기화 중지는 새로운 카메라 보정만 멈추며 이미 실행 중인 웹 타이머를 자동 정지시키지 않습니다. 타이머를 멈추려면 웹에서 정지하세요.

자동 모드를 사용하려면 이번 웹 코드가 배포/실행 중이어야 하고 **OBS 호스트 PC 화면도 새로고침**해야 합니다. 이전 호스트는 카메라 값 표시 기능이 있더라도 자동 재생 기능이 없을 수 있으며, 이 경우 연결 안내에서 새로고침을 요청합니다.

## 인식과 지연

- **RapidOCR 3.9.2 / PP-OCRv6 small / ONNX Runtime CPU**로 선택한 한 줄만 인식합니다. 전체 화면 탐지·방향 분류는 추론에서 생략합니다. [공식 문서](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/)
- 자동 모드에는 정면 7세그먼트 LED를 위한 기하학적 보조 인식기가 있습니다. 신뢰도 높은 두 결과가 충돌하면 건너뜁니다. `OCR 모델만` / `7세그먼트만`도 선택할 수 있습니다. 7세그먼트 점수는 확률로 보정된 모델 신뢰도가 아닌 형태 적합도입니다.
- 기본 약 5.5회/초로 **한 프레임씩** 처리합니다. 처리 중 새 프레임은 큐에 쌓지 않습니다. **최근 1초의 관측을 비교**하며 최초 값과 정수 1초 감소는 3개 프레임(최소 240ms), 샷클락 14·24 리셋과 가림 뒤 복구는 4개 프레임(최소 450ms)으로 확인합니다. 매번 1초를 기다리는 방식이 아니라 증거가 충분하면 즉시 확정합니다.
- 정수는 같은 값 또는 1초 감소를 정상 진행으로 처리합니다. 자동 모드에서 더 큰 감소는 4개 프레임 확인 후 보정 후보로 넘기고, 실제 보정은 예측값과 2초 이상 차이 날 때만 수행합니다. 샷클락의 0~24초 정수 구간은 증가하거나 1.2초 이상 확정값이 없었던 경우 리셋/복구 후보로 취급합니다. 이때 같은 값뿐 아니라 시간에 맞는 감소 흐름도 4개 프레임(최소 450ms)으로 확인하며, 한두 프레임 오독·빠른 감소·충돌하는 후보는 계속 걸러냅니다. 이 완화는 카메라 값만 표시 모드에도 적용합니다. 경기 시계와 24초를 넘는 값에는 기존 감소 규칙을 유지하며, 임의의 새 시작 시간은 **현재 값으로 다시 맞추기**로 기준을 초기화합니다.
- 소수는 동일 숫자에 투표하지 않고 시간에 맞게 감소하는 관측 경로를 비교합니다(예: `4.9 → 4.7 → 4.5`). 후보 구간에서 신뢰도 가중 지지가 70% 미만이면 보류합니다. 가림·낮은 신뢰도는 투표에 넣지 않고, 오래된 값이나 예측값을 새 촬영값처럼 전송하지 않습니다. 반복 오인식이 정상 시간 흐름과 구분되지 않으면 여전히 오독할 수 있습니다.
- 빈 여백을 먼저 줄여 작은 콜론·소수점이 리사이즈 과정에서 사라지는 것을 줄입니다. 영상에서 구분자가 확인되면 숫자 부분을 나눠 읽고 다시 조합합니다. 같은 숫자열에 구분자만 누락된 OCR 결과는 이 영상 근거로 보완하며, 숫자 자체가 다르면 보류합니다.
- 인식 불가, 낮은 신뢰도, 허용 범위 초과, 오래된 프레임은 건너뜁니다. 보이지 않는 콜론·소수점이나 `O→0` 같은 문자를 임의로 만들지 않습니다. **읽은 후보**와 보류 사유를 표시하므로 인식 실패와 범위 초과를 구분할 수 있습니다.
- 로컬 처리 결과가 900ms 이상 오래되면 전송하지 않으며, 웹 호스트는 촬영 후 1초를 초과한 결과·이전 호스트 결과·역순 결과·수동 조작 이전에 찍힌 결과를 버립니다.
- 호스트와 로컬 프로그램의 시계는 왕복 시간으로 맞춥니다. 실행 중인 시계는 촬영~도착 지연만큼 추가 보정합니다. 추가 영상 지연은 선택적인 카메라 버퍼 보정이며 이 짧은 처리·통신 시간과 별개입니다. 같은 표시 단위(정수/0.1초)에 속하면 저장값을 다시 쓰지 않습니다.
- 카메라의 콜론/소수 자릿수도 웹과 OBS 출력에 유지합니다. 샷클락에 `50.1`을 연결해도 `51`로 반올림 표시하지 않습니다. 첫 관측에서 표시 형식이 바뀌면 형식 메타데이터를 한 번 기록합니다. 웹에서 수동 초기화/조정하면 기존 종목별 표시 형식으로 돌아갑니다.
- 이 Mac의 **합성 일반 글꼴/7세그먼트 테스트**에서 추론 약 **7~10ms**, 18개 샘플(빈 화면 포함)을 확인했습니다. 180ms 샘플 간격에서 보통 3개 프레임 확인은 약 360ms, 리셋·복구 4개 확인은 약 540ms에 추론·통신 시간이 더해집니다. 실제 카메라·폰 스트림·중계 네트워크까지 1초 이내임을 보장하는 실측은 아직 아닙니다.
- 구분자 분리 인식을 적용한 합성 시간·소수 샘플은 추가 추론을 포함해 약 **20~30ms**였습니다. 넓은 여백, 작은 글자, 흐림, JPEG 압축, 밝은 배경에 대한 실제 모델 회귀 테스트도 포함합니다. 실제 전광판 영상 정확도는 별도 검증이 필요합니다.

실제 촬영은 숫자 높이 최소 40px 정도, 흔들리지 않는 고정 카메라, 가급적 정면 구도를 권장합니다. LED 스캔/셔터에 의한 일부 획 누락, 강한 반사, 심한 원근, 콜론 점멸에는 오독이 남을 수 있습니다. 미리보기에서 원본 색상/대비 강화와 영역을 조절하세요. 샷클락과 게임클락의 영역·필터 이력·정지/재생 판단·위상은 각각 독립적입니다. 선택한 시계의 다시 맞추기는 다른 시계 상태를 지우지 않습니다.

## 폰 카메라 확장

- **폰을 노트북의 웹캠 장치로 연결**하면 같은 카메라 목록에서 선택합니다. 인식과 동기화는 그대로 사용합니다.
- **폰/IP 카메라 스트림** 모드에 직접 MJPEG HTTP(S) 또는 RTSP 주소를 입력할 수 있습니다. OpenCV가 최신 프레임만 보관하며 끊기면 재연결합니다. 일반 카메라 웹사이트 URL, HLS 재생 페이지, 브라우저 전용 WebRTC 사이트는 직접 입력할 수 없습니다.
- 스트림 시간은 로컬 수신/디코딩 기준입니다. 폰/전송 장치가 이미 버퍼링한 지연이나 정지 영상을 새 프레임으로 반복하는 상황은 검출할 수 없으므로 저지연 스트림을 사용해야 합니다. 이 입력 경로는 구현되어 있으나 실제 폰 장비로는 미검증입니다.
- 별도 사이트가 폰 카메라를 중계하는 경우 그 사이트의 WebRTC/미디어 수신 어댑터를 `stream.py` 입력 경계에 붙일 수 있습니다. 이번 버전은 폰 브라우저용 WebRTC 중계 서버까지 만들지는 않습니다.

로컬 서버는 `127.0.0.1`만 수신하며 외부 공개가 필요 없습니다. 브라우저→로컬 요청은 프로세스별 토큰과 동일 출처 검사를 거칩니다. 공유 링크는 기존 원격 컨트롤과 같은 제어 권한이므로 해당 링크를 가진 로컬 프로그램만 세션에 연결하세요. 영상 저장 기능은 없습니다.

## 웹 연동 계약

기존 `/api/remote-ws`를 그대로 사용하므로 추가 OCR 서버나 HTTP 엔드포인트를 배포할 필요가 없습니다. 웹 변경점은 `clockSync.ts`의 `observe` 연산과 `observationVersion: 1`, `trackingVersion: 2` 기능 표시에 집중되어 있습니다. 기존 수동 리모컨의 프로토콜 버전은 유지합니다.

1. `join` 메시지를 기존 `protocolVersion: 3`, `role: "remote"`, `sessionId`, 임의 `clientId`로 전송합니다.
2. `clock-sync`의 `requestId`에 대응하는 `clock-state.replyTo`로 현재 `epoch`와 호스트 시차를 얻습니다. `observationVersion === 1`인 호스트만 사용합니다. 자동 모드는 추가로 `trackingVersion === 2`을 요구합니다.
3. 아래 `clock-command`를 전송합니다. `mode: "run"`은 정수 타이머를 시작하고, `"hold"`는 정확한 관찰값에서 정지합니다. 소수의 `"run"` 요청은 거부합니다. 정수 `run`에만 `offsetMs`를 넣어 추정 위상과 선택적 추가 지연을 합산하며, 호스트는 촬영 이후 경과 시간을 별도로 계산합니다. `issuedAt`과 `capturedAt`은 반드시 호스트 시차를 반영한 ms 값입니다. `resolutionMs`는 정수/분:초이면 1000, 소수 한 자리이면 100입니다.

```json
{
  "type": "clock-command",
  "command": {
    "id": "unique-frame-uuid",
    "epoch": "host-epoch-from-snapshot",
    "issuedAt": 1234567890500,
    "key": "OBS_BASKETBALL_SHOT_CLOCK",
    "operation": {
      "action": "observe",
      "seconds": 50.1,
      "resolutionMs": 100,
      "format": "seconds",
      "capturedAt": 1234567890450,
      "mode": "hold"
    }
  }
}
```

호스트가 현재 표시값과 비교하여 필요한 경우에만 변경하고 `clock-state`를 방송합니다. 로컬 상태의 전송 수는 수신 확인 수가 아닙니다. 실제 반영 결과는 **웹 시계** 표시로 확인합니다. 과거 호스트나 지연 결과는 무시되며, 원격 저장소의 시계 값을 직접 덮어쓰지 않습니다.

## 검증

```bash
pnpm test:clocks
pnpm test:camera
local-clock/.venv/bin/python local-clock/benchmark.py --segments
local-clock/.venv/bin/python local-clock/benchmark.py --image /absolute/path/to/cropped-clock.jpg
pnpm exec tsc --noEmit
```

`test:camera`는 Python 단위 테스트와 실제 OCR 서버→Python WebSocket 클라이언트→프로젝트 중계→호스트 시계 통합 테스트를 실행합니다. 테스트용 세션과 서버만 생성하며 실제 사용자 세션·OBS·카메라는 사용하지 않습니다.
