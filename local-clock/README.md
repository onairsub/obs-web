# 로컬 전광판 Clock Reader

노트북/USB 카메라의 선택 영역을 읽어 OBS Web 농구 샷클락 또는 경기 시계에 반영합니다. Python 프로그램이 이 컴퓨터에서 OCR을 실행하고, 브라우저 화면에서 카메라·영역·세션을 설정합니다. 영상이나 OCR 모델은 웹 배포 서버로 보내지 않습니다.

## 실행

Python 3.10 이상이 필요합니다. 이 프로젝트에서는 macOS ARM64 / Python 3.12에서 검증했습니다.

프로젝트 루트에서:

```bash
pnpm clock:reader
```

또는 `bash local-clock/run.sh`. 첫 실행은 `local-clock/.venv`에 라이브러리와 패키지에 포함된 ONNX 모델을 설치하므로 인터넷이 필요합니다. 이후 인식은 오프라인으로 동작하며, 배포된 웹 세션 연결에는 네트워크가 필요합니다. 전역 Python 환경은 변경하지 않습니다.

브라우저에서 **http://127.0.0.1:8765** 를 엽니다. Chrome/Safari 등 카메라 권한을 지원하는 브라우저를 권장합니다. Codex 내부 브라우저에서 카메라가 열리지 않으면 일반 브라우저에서 같은 주소를 여세요. 종료는 실행 터미널에서 `Ctrl+C`입니다. 포트 변경: `pnpm clock:reader --port 8766`.

Windows에서는 다음 명령을 사용합니다:

```powershell
py -3 -m venv local-clock/.venv
local-clock\.venv\Scripts\python -m pip install -r local-clock/requirements.txt
local-clock\.venv\Scripts\python local-clock/app.py
```

## 사용 순서

1. OBS Web 호스트에서 농구 화면과 원격 컨트롤을 열고 공유 링크를 복사합니다. 이 브랜치의 웹 코드가 실행/배포되어 있어야 합니다. 호스트 화면도 계속 열어둡니다.
2. 로컬 화면에서 **카메라 켜기**를 누르고 카메라 권한을 허용합니다. 여러 장치가 있으면 카메라 목록에서 선택합니다.
3. 숫자 한 줄을 드래그합니다. 콜론/소수점은 포함하고, 점수·팀 이름·다른 시계는 제외합니다. 영역을 백분율 좌표로 입력할 수도 있으며, 마지막 영역은 이 브라우저에 저장됩니다.
4. 공유 링크를 넣고 **세션 연결**을 누릅니다. 세션 ID만 넣었다면 접속할 중계 서버 주소도 입력합니다. 기존 `NEXT_PUBLIC_REMOTE_ORIGIN`이 설정된 경우 그 주소에서 생성된 공유 링크를 사용하세요.
5. **샷클락** 또는 **경기 시계**를 선택하고, 미리보기에서 읽힌 숫자와 신뢰도를 확인합니다. `7:00 → 420초`, `3:43 → 223초`, `50.1 → 50.1초`, `24 → 24초`입니다. 샷클락 기본 동기화 최대치는 60초, 경기 시계는 1200초이며 변경할 수 있습니다. 최대값을 초과해도 인식값 자체는 표시하고 전송만 보류합니다. 예를 들어 샷클락 대상으로 `7:00`을 읽으면 `420초 인식됨 · 최대값 60초 초과`로 안내합니다.
6. **동기화 시작**을 누릅니다. 영역·입력·인식 설정 변경이나 페이지 새로고침은 동기화를 끄므로 확인 후 다시 시작하세요. 중계 재연결은 자동이며 연결 중에 쌓인 결과는 재전송하지 않습니다.

카메라 없이 확인하려면 영상 입력에서 **테스트 전광판**을 선택하고 영상 열기 → 영역 선택을 합니다. `50.1`, `7:00` 등 텍스트를 직접 바꾸거나 **숫자 가리기**로 누락 처리를 확인할 수 있습니다.

## 두 동작 모드

| 모드 | 동작 | 숫자가 가려졌을 때 |
| --- | --- | --- |
| 카메라 값 그대로 표시 (기본) | 첫 확인값부터 웹 타이머를 정지하고 관측한 값으로 갱신 | 마지막 숫자 유지 |
| 현재 시작/정지 유지 | 실행 중인 타이머는 계속 흐르게 두고 값이 다를 때만 보정. 웹에서 시작/정지 조작 | 기존 타이머 동작 유지 |

기본 모드는 실제 전광판의 멈춤도 자연스럽게 반영합니다. 유지 모드는 더 부드러운 카운트다운을 제공하지만 카메라만으로 실행/정지를 추정하지 않습니다. 동기화 중지는 관측값 전송만 멈추며 이전 실행 상태를 자동 복원하지 않습니다. 필요하면 웹에서 다시 시작하세요.

## 인식과 지연

- **RapidOCR 3.9.2 / PP-OCRv6 small / ONNX Runtime CPU**로 선택한 한 줄만 인식합니다. 전체 화면 탐지·방향 분류는 추론에서 생략합니다. [공식 문서](https://rapidai.github.io/RapidOCRDocs/main/install_usage/rapidocr/usage/)
- 자동 모드에는 정면 7세그먼트 LED를 위한 기하학적 보조 인식기가 있습니다. 신뢰도 높은 두 결과가 충돌하면 건너뜁니다. `OCR 모델만` / `7세그먼트만`도 선택할 수 있습니다. 7세그먼트 점수는 확률로 보정된 모델 신뢰도가 아닌 형태 적합도입니다.
- 기본 약 5.5회/초로 **한 프레임씩** 처리합니다. 처리 중 새 프레임은 큐에 쌓지 않습니다. 최초 값과 큰 변화(24/14 리셋 등)는 두 번 연속 확인합니다. 소수 카운트다운은 매번 값이 달라져도 시간상 가능한 감소이면 통과합니다.
- 빈 여백을 먼저 줄여 작은 콜론·소수점이 리사이즈 과정에서 사라지는 것을 줄입니다. 영상에서 구분자가 확인되면 숫자 부분을 나눠 읽고 다시 조합합니다. 같은 숫자열에 구분자만 누락된 OCR 결과는 이 영상 근거로 보완하며, 숫자 자체가 다르면 보류합니다.
- 인식 불가, 낮은 신뢰도, 허용 범위 초과, 오래된 프레임은 건너뜁니다. 보이지 않는 콜론·소수점이나 `O→0` 같은 문자를 임의로 만들지 않습니다. **읽은 후보**와 보류 사유를 표시하므로 인식 실패와 범위 초과를 구분할 수 있습니다.
- 로컬 처리 결과가 900ms 이상 오래되면 전송하지 않으며, 웹 호스트는 촬영 후 1초를 초과한 결과·이전 호스트 결과·역순 결과·수동 조작 이전에 찍힌 결과를 버립니다.
- 호스트와 로컬 프로그램의 시계는 왕복 시간으로 맞춥니다. 유지 모드에서 실행 중인 시계는 촬영~도착 지연만큼 보정합니다. 같은 표시 단위(정수/0.1초)에 속하면 저장값을 다시 쓰지 않습니다.
- 카메라의 콜론/소수 자릿수도 웹과 OBS 출력에 유지합니다. 샷클락에 `50.1`을 연결해도 `51`로 반올림 표시하지 않습니다. 첫 관측에서 표시 형식이 바뀌면 형식 메타데이터를 한 번 기록합니다. 웹에서 수동 초기화/조정하면 기존 종목별 표시 형식으로 돌아갑니다.
- 이 Mac의 **합성 일반 글꼴/7세그먼트 테스트**에서 추론 약 **7~10ms**, 18개 샘플(빈 화면 포함)을 확인했습니다. 180ms 샘플 간격과 두 프레임 확인을 포함하면 로컬 기준 대략 수백 ms를 목표로 합니다. 실제 카메라·폰 스트림·중계 네트워크까지 1초 이내임을 보장하는 실측은 아직 아닙니다.
- 구분자 분리 인식을 적용한 합성 시간·소수 샘플은 추가 추론을 포함해 약 **20~30ms**였습니다. 넓은 여백, 작은 글자, 흐림, JPEG 압축, 밝은 배경에 대한 실제 모델 회귀 테스트도 포함합니다. 실제 전광판 영상 정확도는 별도 검증이 필요합니다.

실제 촬영은 숫자 높이 최소 40px 정도, 흔들리지 않는 고정 카메라, 가급적 정면 구도를 권장합니다. LED 스캔/셔터에 의한 일부 획 누락, 강한 반사, 심한 원근, 콜론 점멸에는 오독이 남을 수 있습니다. 미리보기에서 원본 색상/대비 강화와 영역을 조절하세요. 현재 버전은 한 영역·한 시계만 동시에 연결합니다.

## 폰 카메라 확장

- **폰을 노트북의 웹캠 장치로 연결**하면 같은 카메라 목록에서 선택합니다. 인식과 동기화는 그대로 사용합니다.
- **폰/IP 카메라 스트림** 모드에 직접 MJPEG HTTP(S) 또는 RTSP 주소를 입력할 수 있습니다. OpenCV가 최신 프레임만 보관하며 끊기면 재연결합니다. 일반 카메라 웹사이트 URL, HLS 재생 페이지, 브라우저 전용 WebRTC 사이트는 직접 입력할 수 없습니다.
- 스트림 시간은 로컬 수신/디코딩 기준입니다. 폰/전송 장치가 이미 버퍼링한 지연이나 정지 영상을 새 프레임으로 반복하는 상황은 검출할 수 없으므로 저지연 스트림을 사용해야 합니다. 이 입력 경로는 구현되어 있으나 실제 폰 장비로는 미검증입니다.
- 별도 사이트가 폰 카메라를 중계하는 경우 그 사이트의 WebRTC/미디어 수신 어댑터를 `stream.py` 입력 경계에 붙일 수 있습니다. 이번 버전은 폰 브라우저용 WebRTC 중계 서버까지 만들지는 않습니다.

로컬 서버는 `127.0.0.1`만 수신하며 외부 공개가 필요 없습니다. 브라우저→로컬 요청은 프로세스별 토큰과 동일 출처 검사를 거칩니다. 공유 링크는 기존 원격 컨트롤과 같은 제어 권한이므로 해당 링크를 가진 로컬 프로그램만 세션에 연결하세요. 영상 저장 기능은 없습니다.

## 웹 연동 계약

기존 `/api/remote-ws`를 그대로 사용하므로 추가 OCR 서버나 HTTP 엔드포인트를 배포할 필요가 없습니다. 웹 변경점은 `clockSync.ts`의 `observe` 연산과 `observationVersion: 1` 기능 표시에 집중되어 있습니다. 기존 수동 리모컨의 프로토콜 버전은 유지합니다.

1. `join` 메시지를 기존 `protocolVersion: 3`, `role: "remote"`, `sessionId`, 임의 `clientId`로 전송합니다.
2. `clock-sync`의 `requestId`에 대응하는 `clock-state.replyTo`로 현재 `epoch`와 호스트 시차를 얻습니다. `observationVersion === 1`인 호스트만 사용합니다.
3. 아래 `clock-command`를 전송합니다. `issuedAt`과 `capturedAt`은 반드시 호스트 시차를 반영한 ms 값입니다. `resolutionMs`는 정수/분:초이면 1000, 소수 한 자리이면 100입니다.

```json
{
  "type": "clock-command",
  "command": {
    "id": "unique-frame-uuid",
    "epoch": "host-epoch-from-snapshot",
    "issuedAt": 1234567890500,
    "key": "OBS_BASKETBALL_SHOT_CLOCK",
    "operation": {
      "action": "observe",
      "seconds": 50.1,
      "resolutionMs": 100,
      "format": "seconds",
      "capturedAt": 1234567890450,
      "mode": "hold"
    }
  }
}
```

호스트가 현재 표시값과 비교하여 필요한 경우에만 변경하고 `clock-state`를 방송합니다. 로컬 상태의 전송 수는 수신 확인 수가 아닙니다. 실제 반영 결과는 **웹 시계** 표시로 확인합니다. 과거 호스트나 지연 결과는 무시되며, 원격 저장소의 시계 값을 직접 덮어쓰지 않습니다.

## 검증

```bash
pnpm test:clocks
pnpm test:camera
local-clock/.venv/bin/python local-clock/benchmark.py --segments
local-clock/.venv/bin/python local-clock/benchmark.py --image /absolute/path/to/cropped-clock.jpg
pnpm exec tsc --noEmit
```

`test:camera`는 Python 단위 테스트와 실제 OCR 서버→Python WebSocket 클라이언트→프로젝트 중계→호스트 시계 통합 테스트를 실행합니다. 테스트용 세션과 서버만 생성하며 실제 사용자 세션·OBS·카메라는 사용하지 않습니다.
